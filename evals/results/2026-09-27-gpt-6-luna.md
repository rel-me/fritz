## Scope and settings

Both runs used the current checkout’s staged, signed `dist/Fritz.app/Contents/Resources/fritz-harness`, the OpenAI Responses adapter, and exactly `gpt-6-luna`. Each run covered 12 synthetic cases, with two independent repetitions per case, 12 model turns, 64 tool calls, and a 180-second deadline per attempt. Output was limited to 8,192 tokens per model turn. Sampling and reasoning used provider defaults. No retries, provider substitutions, or model substitutions occurred. The harness does not expose the resolved model ID.

Credentials were loaded from the explicitly supplied local key file and passed only through the private harness pipe. Reports contain no credentials. Project/data directories and conversation state were fresh for every attempt.

## Finding and change

In baseline `edit-one-section-2`, the model put `4: Afternoon\n5: Room: Blue` into `edit_file.old_text`, copying display-only line numbers from `read_file`. The tool rejected the mismatch without writing. The model then read again, removed the prefixes, edited the intended section, and verified it. Final file contents were correct and unrelated content was unchanged.

Fritz’s tool descriptions and mismatch feedback now explicitly distinguish displayed line numbers from literal file contents. Both follow-up scoped edits used correct text without an error. The corpus moved from revision 1 to revision 2 to allow harmless read-only inspection where the prompt permits it: the baseline also incorrectly penalized `list_files`. The original failed verdict is retained. Even with that rubric correction, the baseline attempt would still fail the zero-unexpected-errors criterion.
